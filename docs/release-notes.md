# 可乐音乐 kele-music · 版本更新日志

在线音乐客户端（Flutter），一套代码构建 **Android / iOS / macOS / Windows / Linux / Web**。
后端基于开源 [api-enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced)，默认接口 `https://music.2000321.xyz`，可在「设置 → 后端服务 → API 地址」随时切换。

## v1.4.2（2026-11-05）

### 新增功能

- **iPhone 锁屏与灵动岛显示正在播放**：iPhone 的锁屏界面与灵动岛可显示当前歌曲的封面、歌名、播放进度，以及正在播放的那句歌词，不用解锁也能看清听到哪里。该功能尚待 iPhone 真机确认显示效果。

### 功能优化

- **播放按钮点按立即响应**：点播放或暂停后按钮立刻切换，不再等歌曲准备；歌曲还在获取音源时，封面上会显示加载提示，准备好后自动消失，期间仍可随时暂停。
- **获取失败有提示、状态能恢复**：歌曲加载失败或等待过久时会明确提示原因，按钮自动回到与实际播放一致的状态，不会出现「显示在播却没有声音」的错位。
- **长时间后台后播放更可靠**：应用在后台停留较久再回到前台时，会先核对当前播放状态并在需要时自动恢复，同时重新申请系统声音控制权，回到应用后点播放即可正常出声。
- **通知关闭时给出引导**：若系统通知权限被关闭，回到应用时会提示前往设置开启，避免后台播放的通知与控制被系统拦截。

### 问题修复

- **长时间后台后点播放没反应**：修复「暂停后把应用放到后台较久，回到应用点播放没有任何反应，只能拖动进度条或重启应用才能恢复」的问题；现在会先检查播放是否真的正常，异常时自动重新准备并回到原来的进度继续播放，仍失败时会给出提示，可直接再点播放重试。
- **部分机型歌词与进度不对齐**：修复部分机型上播放页歌词高亮行与进度不同步、滚动位置偏移的问题，歌词与进度现在保持一致。

## v1.4.1（2026-11-03）

### 问题修复

- 修复「暂停 1 小时后点迷你条播放无反应，须拖动进度条才能续播」与「切换前后台多次后音乐停顿乃至暂停」两个后台恢复问题：原逻辑每次回前台都强制重载音源并重设加载时间戳，反而绕开播放器自带的过期重载自愈、造成重缓冲卡顿；现去掉该强制重载，回前台直接保留播放现场，长挂起后由过期重载分支自动重建，两个问题一并解决。并同步加固 `play()` 末尾自愈——将 `processingState==idle`（音源未就绪的「假播放」）纳入「未真正播放」判定、且改为直接重装载（不再用同位置 seek 这种空操作唤醒），彻底堵住引擎被系统回收后「点了无声」的残留缝隙。涉及 `lib/data/player_repository.dart` 的 `reactivateForForeground()` 与 `play()` 自愈逻辑、`lib/providers.dart` 生命周期注释。
- 补齐后台播放的平台级保障（此前缺失，属更严重的隐性缺陷）：① iOS 新增 `UIBackgroundModes: audio`，否则在 iOS 上一切入后台音乐即被系统挂断、回来早已停止；② 启动时显式 `AudioSession.configure(AudioSessionConfiguration.music())` 配置播放类别与音频焦点；③ 接管系统音频打断（来电 / 其他 App 抢焦点）——打断开始自动暂停、结束若此前在播则自动续播，避免「来电后音乐停了不续、或显示播放却无声」。④ 进一步细分打断语义：提示音闪避（如导航播报，`AudioInterruptionType.duck`）改为**压低音量而非暂停**、结束后还原；音频输出设备断开（拔耳机 / 蓝牙断开）经 `becomingNoisyEventStream` 触发**立即暂停**（不自动恢复），避免声音突然从外放播出。⑤ 两项均对齐参考项目 kele-audio 的 `onFocusDucked` 与 `onNoisy` 处理。涉及 `lib/data/player_repository.dart` 的 `configureSession()` / `_onInterruption()` / `_onNoisy()` 与 `lib/main.dart` 启动调用、`ios/Runner/Info.plist`。
- 修复「退出 App 数小时后重新打开，点迷你条播放无反应、须拖动进度条才出声」的**冷启动**场景：进程被杀后 `restoreQueue` 以无声方式装载音源，底层音频会话/引擎处于「假就绪」（playing 乐观为 true 却无声），首次 `play()` 直接 `play()` 既不被过期重载分支命中、也不被 `trulyNotPlaying`（playing 为真、processingState 非 idle）检出，于是无声且无法自愈——拖动进度条因强制重建底层才出声。现新增 `_needsColdStartReload` 标记冷启动恢复态，首次 `play()` 检测到即强制重建底层音频（等同拖动的唤醒效果），覆盖这一独立的触发路径；切歌等正常装载会在 `_doPlayAt` 成功后置回 false，不会残留导致重复重载。涉及 `lib/data/player_repository.dart` 的 `restoreQueue()`、`play()` 冷启动分支与 `_doPlayAt()`。
- 进一步根治「长后台/系统回收后点播放无声」的**假播放死锁**（此前的重载/自愈仍漏掉该场景）：just_audio 在 App 被系统挂起、音频焦点或输出被收回后会进入「假播放」——`playing` 被乐观置为 true、`processingState` 仍 ready，但音频输出已被切断故无声；而 UI 播放按钮依据 `playbackState.playing`（= `_player.playing && _loadedSongId != null`）此时显示的是**暂停图标**，用户点击实际调 `pause()`，形成「点了没反应、拖动进度条才出声」的死锁（这也解释了「杀进程冷启动能播、后台存活却不行」——冷启动是全新引擎 + 强制重载，后台存活是脏引擎 + 直接 play）。本次引入：① `play()` 末尾**单次进度确认**（`_confirmPlaybackStarted`：play 后 350ms 比对 position 是否真推进，未推进即强制重建底层，覆盖 `playing`/`idle` 标志判断与同位置 seek 都无法识别的假播放；仅确认一次、非循环看门狗）；② 回前台（`reactivateForForeground`）若看似在播则标记可疑停滞并异步确认，真播自动恢复、假播重建，打破死锁；③ `_suspectStall` 标志使假播放下 UI 回显 ▶，确保用户点击走 `play()` 而非 `pause()`；④ 重载成功（`_doPlayAt` 装载完成）即清除该标志。涉及 `lib/data/player_repository.dart` 的 `play()` / `_confirmPlaybackStarted()` / `reactivateForForeground()` / `_onPlaybackEvent()` / `_doPlayAt()`。

## v1.4.0（2026-11-03）

### 新增功能

- **音乐库「收藏 / 创建」拆分**：原「歌单」页签拆分为「收藏」与「创建」两个页签，收藏的歌单与创建的歌单分开管理，入口更清晰、互不混淆。
- **「我喜欢的音乐」固定入口**：未登录时在收藏页签顶部固定展示「我喜欢的音乐」，汇总你收藏过的歌曲；登录用户则随云端歌单原样展示在「创建」页签首位。该歌单不可改名、不可删除。
- **自建歌单可增删改**：创建页签支持新建、重命名、删除自己的歌单；登录用户的自建歌单会与网易云账号同步，换设备也能找回。
- **歌曲一键加入歌单**：在歌曲、歌单、每日推荐等列表的 ⋮ 菜单新增「添加到歌单」，可把歌曲加入任意自建歌单，也能在加入时顺手新建歌单。
- **播放页查看歌曲评论**：播放页工具条新增评论入口，点按打开评论面板即可浏览当前歌曲的听众评论；评论分为「热门」与「最新」两类，各自独立浏览，列表支持滚动持续加载更多，长评论也能顺畅翻看（本地导入的歌曲暂不支持评论）。
- **播放页「更多」菜单**：工具条新增「更多」入口，收纳下载、查看歌曲信息，并新增「添加到歌单」，常用操作集中一处，与专辑页体验一致。

### 功能优化

- **新建歌单入口样式统一**：创建页签与本地页签的「新建」按钮采用一致样式，操作区视觉更统一、更好找。
- **歌单操作轻提示统一**：新建、重命名、删除歌单及把歌曲加入歌单后，屏幕底部都会给出简短提示并自动消失，不打断操作；成功与失败状态清晰可辨，失败时会显示具体原因。
- **收藏页签更清爽**：去掉「我收藏的」栏目标题，歌单列表直接从页签行开始，顶部间距与其他页签一致；「我喜欢的音乐」详情页与自建歌单详情页的标题行留白也与列表对齐。
- **批量下载改为后台异步**：选择多首歌曲后点「下载」立即返回，下载任务转入后台队列逐批进行，页面不再长时间停留，期间可继续浏览、播放其他内容。
- **下载进度一目了然**：「下载管理」页新增批次进度横幅，展示「后台下载中 x/y」与总进度条、成功 / 失败计数；完成的批次显示成功与失败数量，可随时关闭摘要。
- **大批量下载智能分批**：单次选择超过 20 首时先弹出确认提示，确认后转入后台分批下载，避免误触与长时间等待。

### 问题修复

- 修复部分弹窗与提示面板背景过于透明、叠在页面上看不清内容的问题。
- 修复登录用户新建、删除、重命名歌单后列表未及时刷新、看不到变化的问题。
- 修复在「添加到歌单」弹层中新建歌单后，歌曲未加入且没有任何提示的问题。

## v1.2.2（2026-11-02）

### 新增功能
- **新增透明播放缓存**：歌曲真正播放成功后自动将音频字节落盘到应用私有目录，按 LRU 20 首与 256MB 配额管理，与下载管理完全隔离且自动去重，断点续播时优先读取本地缓存、跳过网络缓冲与直链过期。
- **修复「长时间未使用后打开 App 点播放条或播放页播放键无反应」的问题**：根因是进程被系统挂起后音频引擎与音频会话被回收、回前台却未重新激活；现于 App 回到前台时自动重建当前曲播放引擎、并在起播前重新激活音频会话，不再需要手动拖动进度条才能唤醒声音。
- **断点续播升级**：播放状态与进度持久化，App 重启后自动恢复上次歌曲并 seek 到退出时进度，命中本地缓存时零缓冲秒开，无论间隔多久都能快速续播。
- **下载管理支持批量删除**：「下载管理」页长按歌曲或点「管理」进入多选模式，可勾选歌曲（支持全选）后一键批量删除，操作带确认弹窗防误删；勾选的已下载歌曲会连同应用内的缓存文件一并清理、释放存储空间，已保存到系统下载目录的文件不受影响。
- **数据备份与换机迁移**：设置「存储与隐私」新增「导出备份 / 导入备份」，一键把主题、音质等设置偏好、搜索与播放历史、收听统计和登录状态打包成一个备份文件，在新设备上导入即可自动恢复，换手机不用逐项重新配置。
- **备份文件可选密码加密**：导出备份时可设置密码加密，防止备份文件外泄后被他人冒用登录；导入加密备份时输入密码即可，收藏与歌单为云端数据、不受导入影响。

### 功能优化

- **下载管理页焕新**：「已下载」列表去掉卡片底色，直接融入页面背景，浏览更清爽；歌曲行不再显示 VIP 标记，行尾改为显示文件大小（无记录时显示「—」），方便掌握每首歌占用的空间。

### 问题修复

- 无。

### 新增功能

- **客户端检查更新**：设置「关于」板块新增「检查更新」入口，读取 GitHub Releases 最新正式版并与本机版本号比对；发现新版弹窗展示版本号、发布日期、更新说明与产物信息，确认后 Android 应用内下载 APK（实时进度、可随时取消），完成自动拉起系统安装器；Android 8+ 未授权「安装未知应用」时先跳系统设置引导授权，返回即可继续安装，同版本安装包已存在则直接复用、不重复下载；已是最新 / 检查失败均有行内提示与 Toast，可点击重试。更新全程由用户主动触发，**不强制**。**下载默认走国内镜像加速**（`gh-proxy.com` → `gh.ddlc.top` → `ghfast.top`，逐级回退、失败自动切源，进度页实时显示当前下载源，镜像全挂仍回落 GitHub 官方直连），可用 `--dart-define=UPDATE_MIRROR=https://your.mirror/` 追加自有镜像（逗号分隔、优先尝试）；**下载完成后按 GitHub asset 提供的 SHA-256 digest 校验完整性，不匹配自动换源**，防止第三方镜像内容被篡改或截断；检查接口本身为官方 `api.github.com` 优先、失败再走镜像回退。影响范围：全平台均可检查与查看更新说明；应用内下载安装仅 Android，其余平台（Windows / macOS / Linux / Web / iOS）展示说明并跳转 Release 页；涉及 `lib/core/updater.dart`、`lib/core/update_verify*`、设置页与 Android 安装权限 / FileProvider 配置，新增依赖 `url_launcher`、`crypto`。 

### 功能优化

- **迷你播放条播放状态可视化**：封面右下角新增状态角标——播放中为主题色圆徽 + 三柱跳动音符（均衡器律动），暂停为半透明圆徽 + 播放三角（暗示可恢复播放），两种状态经缩放淡入平滑切换；封面本身保持静态，不加呼吸缩放 / 辉光 / 压暗等动效，长时间播放不产生持续视觉干扰。影响范围：全平台迷你播放条 UI，不改变任何播放逻辑。 
- **封面图加载效率优化（`SafeNetworkImage`，效率优先）**：全应用统一的网络封面组件按「效率优先、失败回落占位图」重写。①**按显示尺寸分桶解码**（`cacheWidth`，显示尺寸 × 设备像素比，按 256 阶梯向上取整、封顶 2048）：44px 列表封面不再按原图（常见 1000px+）全量解码，解码内存与时长降一个数量级，图片缓存能驻留数百张封面，长列表滚动不再反复驱逐 / 重下 / 重解码；同一 URL 的 33/44/84px 展示落进同一解码桶共享缓存（`ResizeImage` 以尺寸入 key），避免每种尺寸重复下载；仅传宽不传高，按原图宽高比推导高度、不拉伸变形，原图更小时按原图解码不放大；未限定尺寸的横幅 / 模糊背景 / 唱片封面以屏宽为上限。②**回退候选链从最多 6 条收敛到 3 条 + 成功节点学习**：126 图床仅保留「原 URL → p3 节点（http）→ 原域 https」（p3 为 2026-10-22 真机实测放行节点，砍掉 p1/p2 逐节点轮换与 `?param=` 变体）；任一「协议://节点」首帧出图成功即记为首选并提到候选链最前，后续图片常态 1 次请求直达，不再每次串行试错，失败快速让位占位图。③**加载中去转圈**：原先每张加载中的图各持一个常驻转圈动画，列表多图同载时持续抢帧，改为仅静态占位图。④**裸 Socket 兜底修缮**：字节缓存加上限（32 条、插入序淘汰最旧）避免长期运行无界增长；修正写入键（归一化 origin）与读取键（原始 url）不一致导致跨实例兜底缓存几乎不命中的既有问题，键统一为原始 url；同 url 多实例兜底抓取跨实例去重，只发一次。影响范围：全平台所有走 `SafeNetworkImage` / `CoverImage` 的封面与横幅；真机已验证的「music.126.net 优先 http + Chrome 请求头伪装 + p3 回退」防 403 协议策略原样保留，仅砍掉低价值候选；**效率优先取向下允许个别封面加载失败、显示本地占位图**，`logcat` 过滤 `SafeNetworkImage` 可查失败原因；`flutter analyze` 通过，无接口 / 播放逻辑改动。 
### 问题修复

- **搜索页封面图全部不显示（重要）**：根因是搜索走旧版 `/search` 接口，其返回的 `album` 不含 `picUrl`（仅有一个指向网易云默认灰图的 `img1v1Url`），模型解析出空封面后统一回退到本地占位图，搜索列表所有歌曲显示同一张暗色图；现改用新版 `/cloudsearch` 接口，返回完整 `al.picUrl` 真实专辑封面，数据模型本就兼容 `al/ar/dt` 字段命名，无需改动模型。影响范围：**仅搜索页**（`.search()` 全项目仅搜索页一个调用方，发现页 / 歌单 / 每日推荐等各走各的接口不受影响）；mock 拦截器同步补上 `/cloudsearch` 路径分支，mock 开发模式与单元测试照常可用。

## v0.2.1（2026-10-27）

### 功能优化

- **发现页秒开（缓存优先）**：启动先用本地缓存同步渲染整页（推荐歌单 / 排行榜 / 新歌速递），后台再静默刷新——免费服务器慢时看到的是「立刻出内容」而非全屏转圈；下拉刷新穿透边缘缓存取最新数据。三个内容接口并行拉取、逐板块容错，谁先回来谁先渲染，单板块失败只保留自身占位，不再拖垮整页。
- **登录态恢复提速（头卡秒出）**：登录恢复改为读完本地 Cookie 即刻生效，网络续期移入后台（明确失效才登出，期间请求 301 由统一登出兜底）——此前慢网络下要等一次续期网络往返，冷启动进发现页「每日推荐」头卡迟迟不出现；同时头卡显隐改为实时登录态判定，不再等数据加载跑完，登录态一到立即出现，推荐数据随后补齐。
- **请求提速（边缘缓存）**：内容类接口不再每次附 timestamp，命中服务端 120 秒边缘缓存，免费服务器回源大幅减少；二维码 key、二维码轮询、播放地址等「必须实时」的端点仍强制破缓存，登录与音源时效不受影响。
- **发现页接口真正并行**：限流桶由「全局单桶」改为「按路径分桶」，歌单 / 排行榜 / 新歌 / 每日推荐四个接口互不排队、并行发出。
- **排行榜双排**：主流手机（逻辑宽度 ≥360）排行榜改为双列展示，滚动篇幅约减半；超窄屏与平板自动回退单列。
- **栏目合并：个人专属并入推荐歌单**：发现页由两个相似歌单栏目合为一个，栏目名保留「推荐歌单」；登录态最前固定「每日推荐」「私人雷达」两张头卡，其后仍为原推荐歌单列表，「更多」按钮跳全部歌单页；未登录状态维持原状。
- **音乐库精简**：音乐库仅保留「创建」「收藏」两个页签，移除「歌曲」页签。

### 问题修复

- **发现页加载失败永远空白（重要）**：无缓存且内容接口全部失败时，错误分支此前不可达，页面只剩问候头且无任何提示；现展示整页错误与「重试」按钮，一键恢复。
- **播放页并发加载与强制续播**：起播跳页与播放页自动播放并发时，同一首歌可能被重复解析音源、进度重置，旧曲甚至短暂复活；现按切歌序号丢弃过期的加载结果，只保留最新一次。主动暂停后再进入播放页也不再被强制继续播放（音源未就绪时仍会自动衔接起播）。
- **单曲循环下手动「下一首」变成重播本曲**：现手动切歌按列表循环语义切到下一首（尾部回绕），歌曲自然播完仍按单曲循环重播本曲。
- **起播失败卡在「正在准备播放…」**：歌单详情 / 每日推荐加载失败但已先跳转播放页时，占位页会永远转圈；现显示失败原因与「返回」出口。空歌单提前拦截，不再清空正在播放的队列。
- **推荐歌单登录态只剩一两张**：登录后推荐歌单会按「每日推荐歌单接口」返回逐条去重，两个接口高度重合时列表被裁到只剩一两张（仅完全清空才回退）；现随栏目合并取消该裁剪，全量展示，仅剔除雷达类（雷达改为固定头卡）。
- **301 统一登出后「每日推荐」头卡残留**：停留在发现页时 Cookie 过期被自动登出，头卡与缓存推荐仍会展示，点「每日推荐」必报错；现登出立即隐藏头卡并清理登录态缓存。
- **私人雷达歌单断网不显示**：断网或重启后首次进入发现页，「推荐歌单」头卡位的私人雷达此前无法从缓存还原；现缓存首屏直接回填，离线也能看到。
- **定时停止超过 1 小时显示错误**：90 分钟预设显示成「30:00 后停止播放」、自定义 2 小时显示「00:00」；现正确显示小时位（如「1:30:00 后停止播放」），与定时弹窗格式一致。
- **快速连点迷你播放条重复入栈播放页**：转场窗口内连点会叠加多个播放页；现点击前检查当前路由，不再重复入栈。
- **扫码登录偶发失败**：二维码 key 为无参 GET，受服务端 120 秒缓存影响，短时间内二次登录可能复用已被消费的旧 unikey；现强制破缓存获取新 key。

## v0.2.0（2026-10-23）

### 新增功能

- **VIP / 无版权歌曲智能兜底播放**：播放 VIP 歌曲时官方音源不可用或仅返回试听片段，自动请求后端解灰接口 `/song/url/match` 匹配可用音源（聚合 byfuns / ddyr / gdmusic / msls / oi / qijieya / unm 等多个模块），对全灰歌单"能播尽播"。免费歌曲与可播 VIP 歌曲零额外请求；兜底音源按当前播放音质档位匹配（标准 / 较高 / 极高 / 无损 / Hi-Res）。说明：周杰伦等全网无授权歌曲仍无法播放，会明确提示「该歌曲暂无可用音源」；兜底能力依赖 api-enhanced 后端（默认地址已内置支持）。
- **播放失败全局提示**：新增播放错误广播通道，切歌 / 下一曲 / 队列点歌 / 播放键重试失败时统一弹出 SnackBar 提示，明确区分「点击无反应」与「点击了但没有可用音源」。
- **待播放列表页完善**：复用全应用共用的歌曲行组件，与歌曲列表页完全同源——新增 **VIP 标记** 与行尾**时长**（等宽数字防跳动）；当前播放曲高亮 + 均衡器图标、分隔线对齐方式与其他列表页保持一致。
- **设置页显示当前版本号**：设置底部新增「关于」板块，显示版本与 build 号（取自构建产物内嵌信息，与发布包始终一致），点击一键复制，便于与 GitHub 最新发布比对是否需要更新。

### 功能优化

- **切歌体验**：切歌立即停止旧曲并归零进度，不再出现「旧歌还在响、新歌加载中」的错位感；下一曲音源 URL 预取 + 本地缓存（10 分钟有效期、最多 32 条、并发请求去重），按顺序 / 单曲循环模式智能预取，切歌秒开；音源地址加载失败时自动强制刷新重解析一次。

### 问题修复

- **设置页操作导致声音消失 / 迷你播放条黑屏（重要）**：根因是设置页刷新时销毁并重建播放仓库，音频处理器被释放。应用根部改用全局 ProviderContainer，播放仓库脱离页面级生命周期，设置页任意操作（切主题、改音质、签到等）不再影响正在播放的音乐。
- **无音源歌曲切歌失败后「旧歌复活」**：根因是切歌失败后播放器内部仍保留旧曲状态，此时点播放键会错误恢复旧歌。现跟踪当前已加载曲目，点播放键时若当前曲未加载会自动重新解析加载，失败则提示且绝不复活旧歌。
- **设置页「恢复默认地址」无效**：根因是配置重载从「已被用户保存值污染的当前实例」起步，删除保存键后永远算不回内置默认地址。现改为从纯内置默认幂等重算；同时补齐恢复默认路径的 API 客户端同步（此前仅配置值变化，运行中请求仍走旧地址，需重启才生效）。

### 安装说明

**Android**
1. 下载分 ABI 包：现代手机选 `*-android-arm64-v8a.apk`，老机型选 `*-android-armeabi-v7a.apk`（不再发布 universal 通用包）。
2. 手机「设置 → 允许安装未知来源应用」授权给浏览器/文件管理器。
3. 点击 APK 安装。首次启动可先「游客浏览」，需要同步歌单再登录。

**Windows**
1. 解压 `*-windows-x64.zip` 到任意目录。
2. 双击 `kele-music.exe` 运行（需 Microsoft Visual C++ 2015-2022 x64 运行库，缺失时会提示缺 DLL）。

**macOS**
1. 解压对应架构的 zip，得到 `kele-music.app`。
2. 拖入「应用程序」；首次打开若被拦，右键 → 打开（未做 Apple 公证）。

**Linux**
1. 解压 tar 包后运行 `kele-music`。
2. 依赖：`libsecret-1-0`、`libmpv2`（`sudo apt install libsecret-1-0 libmpv2`），Ubuntu 22.04+ 可直接用。

**Web**
1. 解压 zip，用任意静态服务器托管（如 `npx serve`、Nginx、GitHub Pages）。
2. 打开首页即可游客浏览；建议用 Chrome / Edge。

**iOS**
- 产物是**未签名**的 `.app`，无法直接装到真机。需自行用 Apple 开发者证书签名（如 Xcode 重签、AltStore/Sideloadly 侧载），或等待后续提供 TestFlight / Ad Hoc 包。
