# 可乐音乐 kele-music · 版本更新日志

在线音乐客户端（Flutter），一套代码构建 **Android / iOS / macOS / Windows / Linux / Web**。
后端基于开源 [api-enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced)，默认接口 `https://music.2000321.xyz`，可在「设置 → 后端服务 → API 地址」随时切换。

## v1.2.0（2026-10-30）

### 新增功能

- **收听统计**：设置内新增「收听统计」入口，以趋势图表、概览卡片与每日收听明细呈现听歌时长，走势与明细一目了然。
- **网易云账号绑定**：「设置 → 账号管理」支持绑定与解绑网易云账号，绑定后即可同步歌单与收藏；后续可扩展到更多第三方账号。

### 功能优化

- **「我的」页改为播放统计**：原个人资料区域替换为三张时长卡片（今日播放 / 本周播放 / 本月播放），所有时长统一以分钟呈现。
- **登录入口弱化**：登录入口从首页主区域移入「账号管理」，未登录也能照常浏览与试听，需要同步资料时再登录。

### 问题修复

- 无。

## v1.1.0（2026-10-30）

### 新增功能

- **客户端检查更新**：设置「关于」板块新增「检查更新」入口，读取 GitHub Releases 最新正式版并与本机版本号比对；发现新版弹窗展示版本号、发布日期、更新说明与产物信息，确认后 Android 应用内下载 APK（实时进度、可随时取消），完成自动拉起系统安装器；Android 8+ 未授权「安装未知应用」时先跳系统设置引导授权，返回即可继续安装，同版本安装包已存在则直接复用、不重复下载；已是最新 / 检查失败均有行内提示与 Toast，可点击重试。更新全程由用户主动触发，**不强制**。**下载默认走国内镜像加速**（`gh-proxy.com` → `gh.ddlc.top` → `ghfast.top`，逐级回退、失败自动切源，进度页实时显示当前下载源，镜像全挂仍回落 GitHub 官方直连），可用 `--dart-define=UPDATE_MIRROR=https://your.mirror/` 追加自有镜像（逗号分隔、优先尝试）；**下载完成后按 GitHub asset 提供的 SHA-256 digest 校验完整性，不匹配自动换源**，防止第三方镜像内容被篡改或截断；检查接口本身为官方 `api.github.com` 优先、失败再走镜像回退。影响范围：全平台均可检查与查看更新说明；应用内下载安装仅 Android，其余平台（Windows / macOS / Linux / Web / iOS）展示说明并跳转 Release 页；涉及 `lib/core/updater.dart`、`lib/core/update_verify*`、设置页与 Android 安装权限 / FileProvider 配置，新增依赖 `url_launcher`、`crypto`。 

### 功能优化

- **迷你播放条播放状态可视化**：封面右下角新增状态角标——播放中为主题色圆徽 + 三柱跳动音符（均衡器律动），暂停为半透明圆徽 + 播放三角（暗示可恢复播放），两种状态经缩放淡入平滑切换；封面本身保持静态，不加呼吸缩放 / 辉光 / 压暗等动效，长时间播放不产生持续视觉干扰。影响范围：全平台迷你播放条 UI，不改变任何播放逻辑。 
- **封面图加载效率优化（`SafeNetworkImage`，效率优先）**：全应用统一的网络封面组件按「效率优先、失败回落占位图」重写。①**按显示尺寸分桶解码**（`cacheWidth`，显示尺寸 × 设备像素比，按 256 阶梯向上取整、封顶 2048）：44px 列表封面不再按原图（常见 1000px+）全量解码，解码内存与时长降一个数量级，图片缓存能驻留数百张封面，长列表滚动不再反复驱逐 / 重下 / 重解码；同一 URL 的 33/44/84px 展示落进同一解码桶共享缓存（`ResizeImage` 以尺寸入 key），避免每种尺寸重复下载；仅传宽不传高，按原图宽高比推导高度、不拉伸变形，原图更小时按原图解码不放大；未限定尺寸的横幅 / 模糊背景 / 唱片封面以屏宽为上限。②**回退候选链从最多 6 条收敛到 3 条 + 成功节点学习**：126 图床仅保留「原 URL → p3 节点（http）→ 原域 https」（p3 为 2026-10-22 真机实测放行节点，砍掉 p1/p2 逐节点轮换与 `?param=` 变体）；任一「协议://节点」首帧出图成功即记为首选并提到候选链最前，后续图片常态 1 次请求直达，不再每次串行试错，失败快速让位占位图。③**加载中去转圈**：原先每张加载中的图各持一个常驻转圈动画，列表多图同载时持续抢帧，改为仅静态占位图。④**裸 Socket 兜底修缮**：字节缓存加上限（32 条、插入序淘汰最旧）避免长期运行无界增长；修正写入键（归一化 origin）与读取键（原始 url）不一致导致跨实例兜底缓存几乎不命中的既有问题，键统一为原始 url；同 url 多实例兜底抓取跨实例去重，只发一次。影响范围：全平台所有走 `SafeNetworkImage` / `CoverImage` 的封面与横幅；真机已验证的「music.126.net 优先 http + Chrome 请求头伪装 + p3 回退」防 403 协议策略原样保留，仅砍掉低价值候选；**效率优先取向下允许个别封面加载失败、显示本地占位图**，`logcat` 过滤 `SafeNetworkImage` 可查失败原因；`flutter analyze` 通过，无接口 / 播放逻辑改动。 
### 问题修复

- **搜索页封面图全部不显示（重要）**：根因是搜索走旧版 `/search` 接口，其返回的 `album` 不含 `picUrl`（仅有一个指向网易云默认灰图的 `img1v1Url`），模型解析出空封面后统一回退到本地占位图，搜索列表所有歌曲显示同一张暗色图；现改用新版 `/cloudsearch` 接口，返回完整 `al.picUrl` 真实专辑封面，数据模型本就兼容 `al/ar/dt` 字段命名，无需改动模型。影响范围：**仅搜索页**（`.search()` 全项目仅搜索页一个调用方，发现页 / 歌单 / 每日推荐等各走各的接口不受影响）；mock 拦截器同步补上 `/cloudsearch` 路径分支，mock 开发模式与单元测试照常可用。

## v0.2.1（2026-10-27）

### 功能优化

- **发现页秒开（缓存优先）**：启动先用本地缓存同步渲染整页（推荐歌单 / 排行榜 / 新歌速递），后台再静默刷新——免费服务器慢时看到的是「立刻出内容」而非全屏转圈；下拉刷新穿透边缘缓存取最新数据。三个内容接口并行拉取、逐板块容错，谁先回来谁先渲染，单板块失败只保留自身占位，不再拖垮整页。
- **登录态恢复提速（头卡秒出）**：登录恢复改为读完本地 Cookie 即刻生效，网络续期移入后台（明确失效才登出，期间请求 301 由统一登出兜底）——此前慢网络下要等一次续期网络往返，冷启动进发现页「每日推荐」头卡迟迟不出现；同时头卡显隐改为实时登录态判定，不再等数据加载跑完，登录态一到立即出现，推荐数据随后补齐。
- **请求提速（边缘缓存）**：内容类接口不再每次附 timestamp，命中服务端 120 秒边缘缓存，免费服务器回源大幅减少；二维码 key、二维码轮询、播放地址等「必须实时」的端点仍强制破缓存，登录与音源时效不受影响。
- **发现页接口真正并行**：限流桶由「全局单桶」改为「按路径分桶」，歌单 / 排行榜 / 新歌 / 每日推荐四个接口互不排队、并行发出。
- **排行榜双排**：主流手机（逻辑宽度 ≥360）排行榜改为双列展示，滚动篇幅约减半；超窄屏与平板自动回退单列。
- **栏目合并：个人专属并入推荐歌单**：发现页由两个相似歌单栏目合为一个，栏目名保留「推荐歌单」；登录态最前固定「每日推荐」「私人雷达」两张头卡，其后仍为原推荐歌单列表，「更多」按钮跳全部歌单页；未登录状态维持原状。
- **音乐库精简**：音乐库仅保留「创建」「收藏」两个页签，移除「歌曲」页签。

### 问题修复

- **发现页加载失败永远空白（重要）**：无缓存且内容接口全部失败时，错误分支此前不可达，页面只剩问候头且无任何提示；现展示整页错误与「重试」按钮，一键恢复。
- **播放页并发加载与强制续播**：起播跳页与播放页自动播放并发时，同一首歌可能被重复解析音源、进度重置，旧曲甚至短暂复活；现按切歌序号丢弃过期的加载结果，只保留最新一次。主动暂停后再进入播放页也不再被强制继续播放（音源未就绪时仍会自动衔接起播）。
- **单曲循环下手动「下一首」变成重播本曲**：现手动切歌按列表循环语义切到下一首（尾部回绕），歌曲自然播完仍按单曲循环重播本曲。
- **起播失败卡在「正在准备播放…」**：歌单详情 / 每日推荐加载失败但已先跳转播放页时，占位页会永远转圈；现显示失败原因与「返回」出口。空歌单提前拦截，不再清空正在播放的队列。
- **推荐歌单登录态只剩一两张**：登录后推荐歌单会按「每日推荐歌单接口」返回逐条去重，两个接口高度重合时列表被裁到只剩一两张（仅完全清空才回退）；现随栏目合并取消该裁剪，全量展示，仅剔除雷达类（雷达改为固定头卡）。
- **301 统一登出后「每日推荐」头卡残留**：停留在发现页时 Cookie 过期被自动登出，头卡与缓存推荐仍会展示，点「每日推荐」必报错；现登出立即隐藏头卡并清理登录态缓存。
- **私人雷达歌单断网不显示**：断网或重启后首次进入发现页，「推荐歌单」头卡位的私人雷达此前无法从缓存还原；现缓存首屏直接回填，离线也能看到。
- **定时停止超过 1 小时显示错误**：90 分钟预设显示成「30:00 后停止播放」、自定义 2 小时显示「00:00」；现正确显示小时位（如「1:30:00 后停止播放」），与定时弹窗格式一致。
- **快速连点迷你播放条重复入栈播放页**：转场窗口内连点会叠加多个播放页；现点击前检查当前路由，不再重复入栈。
- **扫码登录偶发失败**：二维码 key 为无参 GET，受服务端 120 秒缓存影响，短时间内二次登录可能复用已被消费的旧 unikey；现强制破缓存获取新 key。

## v0.2.0（2026-10-23）

### 新增功能

- **VIP / 无版权歌曲智能兜底播放**：播放 VIP 歌曲时官方音源不可用或仅返回试听片段，自动请求后端解灰接口 `/song/url/match` 匹配可用音源（聚合 byfuns / ddyr / gdmusic / msls / oi / qijieya / unm 等多个模块），对全灰歌单"能播尽播"。免费歌曲与可播 VIP 歌曲零额外请求；兜底音源按当前播放音质档位匹配（标准 / 较高 / 极高 / 无损 / Hi-Res）。说明：周杰伦等全网无授权歌曲仍无法播放，会明确提示「该歌曲暂无可用音源」；兜底能力依赖 api-enhanced 后端（默认地址已内置支持）。
- **播放失败全局提示**：新增播放错误广播通道，切歌 / 下一曲 / 队列点歌 / 播放键重试失败时统一弹出 SnackBar 提示，明确区分「点击无反应」与「点击了但没有可用音源」。
- **待播放列表页完善**：复用全应用共用的歌曲行组件，与歌曲列表页完全同源——新增 **VIP 标记** 与行尾**时长**（等宽数字防跳动）；当前播放曲高亮 + 均衡器图标、分隔线对齐方式与其他列表页保持一致。
- **设置页显示当前版本号**：设置底部新增「关于」板块，显示版本与 build 号（取自构建产物内嵌信息，与发布包始终一致），点击一键复制，便于与 GitHub 最新发布比对是否需要更新。

### 功能优化

- **切歌体验**：切歌立即停止旧曲并归零进度，不再出现「旧歌还在响、新歌加载中」的错位感；下一曲音源 URL 预取 + 本地缓存（10 分钟有效期、最多 32 条、并发请求去重），按顺序 / 单曲循环模式智能预取，切歌秒开；音源地址加载失败时自动强制刷新重解析一次。

### 问题修复

- **设置页操作导致声音消失 / 迷你播放条黑屏（重要）**：根因是设置页刷新时销毁并重建播放仓库，音频处理器被释放。应用根部改用全局 ProviderContainer，播放仓库脱离页面级生命周期，设置页任意操作（切主题、改音质、签到等）不再影响正在播放的音乐。
- **无音源歌曲切歌失败后「旧歌复活」**：根因是切歌失败后播放器内部仍保留旧曲状态，此时点播放键会错误恢复旧歌。现跟踪当前已加载曲目，点播放键时若当前曲未加载会自动重新解析加载，失败则提示且绝不复活旧歌。
- **设置页「恢复默认地址」无效**：根因是配置重载从「已被用户保存值污染的当前实例」起步，删除保存键后永远算不回内置默认地址。现改为从纯内置默认幂等重算；同时补齐恢复默认路径的 API 客户端同步（此前仅配置值变化，运行中请求仍走旧地址，需重启才生效）。

### 安装说明

**Android**
1. 下载 `*-android-universal.apk`（不确定机型就用这个）。
2. 手机「设置 → 允许安装未知来源应用」授权给浏览器/文件管理器。
3. 点击 APK 安装。首次启动可先「游客浏览」，需要同步歌单再登录。

**Windows**
1. 解压 `*-windows-x64.zip` 到任意目录。
2. 双击 `kele-music.exe` 运行（需 Microsoft Visual C++ 2015-2022 x64 运行库，缺失时会提示缺 DLL）。

**macOS**
